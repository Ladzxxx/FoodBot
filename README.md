# FoodBot

Дневник сна, стабильности настроения, боли в животе и питания на Python/aiogram.
Интерфейс — русский и английский. Ответы сохраняются в SQLite по пользователю
и дате. Это дневник самоотчётов; бот не определяет диагноз или причину боли.

Краткая инструкция и карта мест изменения: [Readmes/README.md](Readmes/README.md).

## Запуск

Используйте Python 3.12–3.14. Текущие зависимости проверены на Python 3.14;
синтаксис активных модулей также проверяется для Python 3.12. Запуск на самом
Linux-сервере ещё не проверялся. Нужен один работающий процесс бота на токен.

Новая установка на Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Укажите свой BOT_TOKEN в .env.
python main.py
```

Новая установка на Windows / PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Укажите свой BOT_TOKEN в .env.
.\.venv\Scripts\python.exe main.py
```

Копирование `.env.example` нужно только при первой установке. При обновлении
сохраните существующие `.env` и `data/calendar.sqlite3`, установите зависимости
и перезапустите `main.py`. Токен можно передать и переменной окружения BOT_TOKEN.
В requirements.txt зафиксированы aiogram, python-dotenv, aiosqlite и openpyxl;
их зависимости устанавливает pip. Проверка окружения: `python -m pip check`.

Пути к базе и Images считаются от файлов проекта, независимо от папки запуска.
При старте создаются отсутствующие таблицы и добавляются нужные столбцы.
Старые записи сохраняются. Остановка — Ctrl+C; цикл напоминаний завершается
до закрытия соединения с Telegram.

## Команды и профиль

| Команда | Действие |
| --- | --- |
| `/start` | Продолжить начальную настройку или открыть календарь настроенного пользователя. Сохранённые ответы остаются. |
| `/callendar` | Открыть календарь из любого диалога. Написание команды сохранено намеренно. |
| `/makenote` | Последние восемь дат с записями, переход к сегодня/вчера и календарю. |
| `/meal [ЧЧ:ММ] [описание]` | Записать еду за текущую местную дату; время можно указать или изменить, описание до 50 символов. |
| `/statistics` | Статистика за всё время, предыдущий месяц и выбор сохранённых месяцев; выгрузка Excel. |
| `/settings` | Повторить настройку. Действующий профиль меняется только после последнего ответа. |
| `/timezone` | Быстро изменить UTC-смещение с сохранением настроек напоминаний. |
| `/language` | Изменить только язык, сохранив опрос, черновики, настройки и напоминания. |
| `/help` | Краткая справка. |
| `/privacy` | Политика конфиденциальности. |
| `/delete_me` | Подтверждённое удаление данных и отзыв согласия. |

Тестовая команда напоминаний удалена. После обновления отправьте `/start`,
чтобы обновились также подсказки команд в личном чате. Постоянная Reply Keyboard
содержит `/meal`, `/callendar`, `/settings`.

Настройка: язык → политика → отдельное согласие → никнейм → UTC-смещение → утро/вечер → час напоминания.
Пол и год рождения временно отключены: их строки закомментированы в
`Forms/profile.py: PROFILE_QUESTIONS`. Переводы, проверка ввода, клавиатура,
изображения и столбцы базы оставлены для возврата. Чтобы вернуть вопросы,
раскомментируйте эти две строки. Старые значения не стираются при `/settings`;
новым пользователям они не придумываются. Старые кнопки пропущенных вопросов
не записывают ответы. Незавершённая прежняя настройка продолжится с UTC-смещения.

Никнейм — 1–64 символа. Часовой пояс — постоянное UTC-смещение: 24 кнопки
в 4 колонки и 6 рядов плюс Москва (+3:00 UTC). Вечерний вариант помечен «рекомендуем» в /start и /settings. Варианты часа: 6–11 утром,
18–23 вечером; Back возвращает к выбору утро/вечер.

## Языки и тексты

Язык хранится только в `user_profiles.language`: ru/en. Для первого приветствия
без сохранённого выбора используется имя Telegram: кириллица — ru, латиница — en,
иначе ru. Догадка не сохраняется вместо явного выбора. При первом входе кнопки
`Русский` / `English` выбирают язык политики во временном состоянии. Профиль,
язык и согласие сохраняются только после нажатия «Согласен».
Сохранённый выбор важнее имени и языка клиента Telegram. Запасной язык — русский.

В `/settings` вопросы используют язык черновика. Фоновые напоминания до
завершения настройки используют язык действующего профиля. `/language` меняет
язык следующих сообщений, не сбрасывая текущий опрос.

Тексты редактируются в `Locales/ru.py` и `Locales/en.py` под `# CAN CHANGE TEXT`.
Для новой строки добавьте одинаковый ключ, например:

```python
# ru.py
"calendar.notice": "Дата: {date}"
# en.py
"calendar.notice": "Date: {date}"
# обработчик
t(lang, "calendar.notice", date=selected_date.strftime("%d.%m.%Y"))
```

Имена подстановок должны совпадать. `t()` работает только со словарями,
не читает SQLite и не использует API. Отсутствие ru-перевода допускает en;
отсутствие ключа в обоих словарях считается ошибкой разработки и проверяется тестами.
Коды состояний, callback_data, yes/no, morning/evening и поля базы не переводятся.
Пользовательские заметки, названия препаратов и еда сохраняются исходными.
Для HTML-сообщений пользовательские подстановки экранируются в месте построения
текста через html.escape(), без повторного экранирования подготовленной разметки.

## Календарь и дневник

Календарь открывается без выбранной даты. Будущие даты недоступны. Только
выбор дня показывает время сна, удовлетворённость сном, стабильность настроения,
наличие боли, затем Meals / «Приёмы пищи» и общую заметку дня до 200 символов.
Длинные старые заметки сокращаются только на экране; в базе текст сохраняется.
Пропуски обозначены `___`. Еда листается по десять записей.

При выборе даты или месяца прежний календарь сначала удаляется, затем приходит
новый. Если Telegram запрещает удаление, обновляется прежнее сообщение.
Кнопки полного просмотра нет; прежний обработчик сохранён для совместимости.
Просмотр, листание и статистика не записывают ответы.

`Edit the day` / «Заполнить день» запускает вопросы:

1. Отход ко сну: от полудня предыдущего дня до полудня выбранного.
   Пробуждение: 00:00–24:00 выбранного дня. Можно нажать час или ввести ЧЧ:ММ.
   До полудня при обычном вводе — выбранный день, после — предыдущий;
   выбранный полдень — кнопка Today / «Сегодня» или `today 12:00` / `сегодня 12:00`.
   Допустимы явные префиксы yesterday/today и вчера/сегодня.
2. Удовлетворённость сном и стабильность настроения — 1–10.
3. Боль в животе: при «Да» — интенсивность 1–10 и вопрос об обезболивающем.
4. Если препарат принимали — название/доза, помогло ли (да/нет/немного),
   повторный вопрос о других препаратах и список записанного.
5. При боли — необязательное описание одного худшего эпизода: область, характер,
   сопутствующие симптомы, предполагаемые пользователем триггеры. Затем — заметка о боли.
6. Последняя в обеих ветках — необязательная общая заметка о дне до 200 символов.

Сон считается по выбранным дням, максимум 36 часов: 20:00 вчера → 21:00 сегодня
даёт 25 часов; 22:00 → 06:00 — 8 часов. Отрицательная длительность не сохраняется,
вопрос повторяется с понятной ошибкой.

Каждый ответ сохраняется сразу, исходный вопрос получает подтверждение и значение.
При перезаписи вопрос сначала показывает «Уже записано», затем — прежнее и новое
значения. Снимок прежних значений живёт только в текущем FSM, без отдельного журнала
истории; после перезапуска используются оставшиеся сохранённые ответы.
Отмена оставляет прогресс. Continue draft / «Продолжить черновик» возобновляет
сохранённый шаг после паузы или перезапуска. Start clean / «Начать заново» очищает
только незавершённый дневник этой даты, его препараты и описание боли; еда остаётся.
Старые и повторные кнопки защищены проверками пользователя, даты, сессии и шага.

В описании боли флажки сохраняются при каждом переключении. Done / «Готово»
подтверждает вопрос, пустой выбор не принимается. None / No clear trigger,
Not sure и Skip исключают обычные варианты. Other допускает 200 символов,
для триггеров — 300. Отдельные области исключают «По всему животу» и наоборот.
Предупреждения при тревожных симптомах сохраняются; бот не делает вывод о диагнозе.
В блоке остаются последнее подтверждение и текущий вопрос; ошибки удаления
сообщений не прерывают запись. Пользовательский текст удаляется только после
сохранения и подтверждения именно этого текста.

Пять условий отметки завершённого дня: сон ≥7 часов, удовлетворённость сном ≥7,
стабильность настроения ≥7, минимум два приёма пищи за дату, отход ко сну до
23:00 предыдущего дня. Все выполнены — ✅; одно не выполнено — 🟨; два — 🟧;
три и более — 🟥. Только красная отметка дня с болью заменяется на 🆘.
Незавершённая запись — 📝, без ответов — без отметки. Легенды в календаре нет.

## Статистика и Excel

Показаны дни с записями, средняя длительность сна и оценки, число оценок ниже 7,
дни с болью, Excellent days / «Отличные дни» по пяти условиям и число записей еды.
Пропуски не становятся нулями. Прежние Yes/No и шкала 1–7 не преобразуются в 1–10.
Кнопка предыдущего месяца подписана его названием. Meal statistics — оставленная
заглушка: только подтверждает нажатие. Pain statistics показывает подтверждённые
выборы по уникальным датам; знаменатель N отдельный для каждого вопроса,
unknown/skipped/in_progress исключены и показаны отдельно. Сумма процентов
при множественном выборе может превышать 100%. Интенсивность считается отдельно.

Get Excel file / «Скачать Excel» в месячной и общей статистике выгружает **всю
историю пользователя**, включая черновики: одна строка на дату с данными,
новые сверху, без промежуточных пустых дат. Входят все ответы, заметки,
лекарства с эффектом, еда, варианты и статусы боли, прежние шкалы отдельно.
Язык считывается при нажатии, даже если кнопка осталась в старом сообщении:
переводятся имя файла, лист, заголовки и подписи. Содержимое заметок не меняется.
Очень длинный текст получает колонки продолжения; формулы из текста не исполняются.
Файл создаётся в памяти и отправляется только владельцу в личный чат.

## Время еды

Можно отправить /meal 13:45 или /meal 13:45 суп. Без времени используется
текущее местное время. После обычного /meal можно ответить временем ЧЧ:ММ
(или временем и описанием) вместо описания. Это изменит уже созданный приём
пищи, не добавляя второй. Время — 00:00–23:59, ровно две цифры часа и минуты.

Кнопка «Изменить время» доступна и при вводе описания, и после сохранения еды.
Она открывает отдельный ввод с отменой. Дата, описание, UTC-смещение и время
создания записи сохраняются. Дата фиксируется при /meal и не меняется после
полуночи или изменения часового пояса. Приёмы пищи показываются по дате/времени еды.
Еда по-прежнему не сбрасывает таймер напоминаний.

## Напоминания и данные

Штатное напоминание приходит после выбранного местного часа, максимум один раз
за местный день, с обращением по нику. И утром, и вечером нужны 24 часа без
завершённой записи; после первой настройки отсчёт идёт от её завершения.
Утром дополнительно проверяются пропуски сна за сегодня и остальных ответов
за вчера. Кнопка открывает отдельный сценарий: сон за дату пробуждения сегодня,
остальные ответы за вчера. Вечером кнопка по-прежнему открывает сегодня. Еда, частичные ответы и просмотр не
сбрасывают таймер. Дата попытки сохраняется до отправки; перезапуск и смена
UTC-смещения не повторяют её. Пропущенные дни не рассылаются. Блокировка бота
отключает отправку, новый /start разрешает её снова. Старая рассылка шаблона отключена.

В `data/calendar.sqlite3` десять таблиц: user_consents, morning_sessions, user_profiles, diary_entries,
day_medications, meals, day_pain_answers, day_pain_options и прежние
calendar_answers / day_ratings. Все ответы разделены по user_id и entry_date.
updated_at записывает время новых ответов; старым данным время не придумывается.
Не удаляйте базу для обновления кода. Резервируйте данные отдельно от Git.

## Утренний сценарий и согласие

Подробности, карта новых файлов и ограничения: [Readmes/MORNING_PRIVACY.md](Readmes/MORNING_PRIVACY.md).
Утренний опрос сохраняет две даты и прогресс в SQLite. Если есть недостающие
ответы, кнопка напоминания сразу открывает очередной вопрос: без большого обзора,
пустых полей и предупреждений о перезаписи. Уже записанные ответы пропускаются.
Краткий экран остаётся для полностью заполненных частей и устаревшего сценария. Календарь и вечерний вход
сохраняют прежнее поведение. Неполный дневник не становится завершённым от одного сна.

До согласия дневник и напоминания закрыты, включая старые кнопки. Существующие
данные сохраняются до выбора пользователя. Отказ удаляет все активные данные
этого пользователя и разрешает начать заново через /start.

Оператор политики: Лозовский Владислав Александрович; контакты @ooosila /
loz_vlad@icloud.com. Еженедельное удаление резервных копий указано со слов
владельца; код не управляет копиями у хостинг-провайдера. Автоматическое удаление базы
не удаляет историю Telegram, скачанные файлы и резервные копии сервера.

## Проверки и Git

```bash
python -B -m unittest discover -s tests -p 'test_*.py' -q
python -m pip check
```

Тесты работают с временными базами и подменённым Telegram. Реальный токен,
рабочая SQLite и отправка в настоящий чат в них не используются. Неожиданный
запрос Telegram в тесте вызывает ошибку вместо обращения к сети.
В `tests/helpers.py` основной тестовый профиль имеет согласие; новые пользователи
проходят настоящие кнопки языка и согласия. `test_privacy.py` отдельно проверяет
отсутствие и устаревание согласия, пробельный ввод, удаление и его ошибки.
`test_morning.py` проверяет две даты, пропуск готовых ответов, восстановление
